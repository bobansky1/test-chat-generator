# Chat Studio

Редактор макетов переписок Telegram в оформлении iPhone. React 19 + TypeScript + Vite. Данные и фотографии хранятся локально в IndexedDB браузера, сервер и аккаунт не нужны.

## Запуск

Требуется Node.js 24 (сервер использует встроенный SQLite). Главная страница находится на `/`, редактор — на `/app`.

```sh
npm install
npm run dev
```

В другом терминале запустите `npm run server` — API оплаты на порту 3001. Vite перенаправляет `/api` на этот сервер. Без настроек ЮKassa редактор работает, но покупка отключена.

Открыть адрес, выведенный Vite (обычно http://127.0.0.1:5173).

```sh
npm run build    # проверка TypeScript и production-сборка в dist/
npm run preview # просмотр сборки
npm test        # проверки формата импорта
```

## Возможности

- Кнопка «Загрузить JSON», перетаскивание файла и вставка JSON. JSON создаётся вне приложения.
- Проверка полей с указанием номера ошибочного сообщения; образец JSON и инструкция для ИИ в разделе «Формат JSON».
- Профиль собеседника, аватар, статус, верификация и закреплённое сообщение.
- Входящие/исходящие сообщения, фото, визуальные голосовые, даты, цитаты, реакции, время и галочки.
- Редактирование по нажатию на сообщение, изменение порядка, удаление, отмена/повтор до 40 действий.
- Светлая/тёмная темы, фоны, время iPhone, Wi-Fi/5G/LTE, сигнал, батарея, зарядка, беззвучный режим и Dynamic Island.
- Плавающие стеклянные панели с размытием и SVG-иконки. Во вкладке «Экран» доступен пресет «Стиль как на референсе» с тёмным фоном и фиолетовыми сообщениями. Эффект стекла сохраняется в PNG и HTML.
- PNG экрана или всей переписки, 1×/2×/3×; HTML с встроенными фото; JSON со всеми ресурсами.
- Повторный импорт собственного HTML без выполнения кода из него.
- Адаптивная панель редактора и автосохранение в браузере.

## Формат JSON

Полный пример: `public/chat-example.json`. Минимальный файл:

```json
{
  "chat": { "name": "Александра", "status": "в сети" },
  "messages": [
    { "sender": "other", "text": "Привет!", "time": "10:24" },
    { "sender": "me", "text": "Привет! 👋", "time": "10:25", "status": "read" }
  ]
}
```

Можно передать просто массив сообщений. Необязательные параметры получают значения по умолчанию.

Для закреплённого сообщения используйте `chat.pinned`. Параметры `screen.muted: true` и `screen.wallpaper: "violet"` включают значок беззвучного режима и фиолетовый фон.

| Поле сообщения | Значения |
| --- | --- |
| `id` | Необязательный уникальный идентификатор |
| `type` | `text` (по умолчанию), `photo`, `voice`, `date` |
| `sender` | `me` (справа), `other` (слева, по умолчанию) |
| `text` | Текст сообщения / подпись / текст разделителя даты |
| `time` | ЧЧ:ММ, по умолчанию 10:00 |
| `status` | `sent`, `delivered`, `read` (по умолчанию) |
| `image` | Имя загружаемого файла или растровый data URL |
| `reply` | Текст цитируемого сообщения |
| `reaction` | Эмодзи |
| `duration` | Визуальная длительность голосового, например 0:12 |

Фотографии `photo.jpg` и аватар `avatar.jpg` загрузите в «Медиатеку» с совпадающими именами. Повторная загрузка того же имени заменяет ресурс. Сохранённый JSON включает изображения в `assets`, повторно загружать их не нужно. Удаление ресурса из медиатеки оставляет ссылку в сообщении: загрузите файл снова или удалите сообщение. Удаление можно отменить в редакторе.

## Экспорт и ограничения

В режиме «Экран iPhone» PNG/HTML содержит текущую видимую область прокручиваемого диалога, включая строку состояния и нижнюю панель. «Вся переписка» создаёт длинное изображение/страницу. Рамка устройства и выделение редактируемого сообщения не экспортируются.

- Размер экрана — 393 логических пикселя по ширине. Это стилизация iOS, не нативное приложение и не гарантия попиксельного совпадения со всеми версиями Telegram/iPhone. На Windows используется системный шрифт; emoji зависят от ОС.
- Голосовые сообщения визуальные, воспроизведения/записи аудио нет.
- PNG — экспорт, не распознавание чужих скриншотов. В HTML можно импортировать только файлы, созданные этим редактором.
- 1000 сообщений, 10 000 символов на сообщение; файл изображения до 10 МБ и 40 Мп, автоматически уменьшается до 1800 px по длинной стороне. GIF сохраняется как статичный кадр.
- Общий объём медиатеки до 50 МБ; JSON до 60 МБ. Очень длинные PNG ограничены высотой 16 000 физических px: используйте 1× или HTML.
- Удалённые URL изображений не загружаются. Используйте локальные файлы: это сохраняет автономность и предотвращает проблемы CORS при экспорте.
- Автосохранение привязано к адресу сайта и профилю браузера. Очистка данных браузера удалит его. JSON — переносимая резервная копия проекта.

## Структура

`src/App.tsx` — редактор; `Phone.tsx` и `phone.css` — экспортируемый экран; `Icons.tsx` — SVG-иконки; `model.ts` — формат и валидация; `export.ts` — PNG/HTML; `storage.ts` — IndexedDB.

`src/Landing.tsx` и `landing.css` — главная страница с GSAP/ScrollTrigger и поддержкой reduced motion. `src/Purchase.tsx` — покупка и активация. `server/` — ЮKassa и ключи, `shared/plans.json` — единый список тарифов для сервера и интерфейса.

## Ключи и подключение ЮKassa

Тарифы: 100 ₽ за один успешно подготовленный файл в выбранном формате; 1 500 ₽ за 24 часа безлимита; 3 000 ₽ за 30 дней безлимита. Срок начинается при первой активации, автопродления нет. Все три формата требуют ключ. Шаблон JSON для импорта остаётся бесплатным.

1. Скопируйте `.env.example` в `.env`. Файл `.env` исключён из Git. Не используйте префикс `VITE_` для секретов.
2. Укажите `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` тестового магазина и `YOOKASSA_TEST=true`.
3. Создайте постоянный случайный `LICENSE_SECRET` минимум из 32 символов (например, `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`). Не меняйте его после выдачи ключей; делайте резервные копии вместе с базой.
4. Укажите `APP_ORIGIN`: точный адрес интерфейса, без завершающего слэша. Для разработки — `http://127.0.0.1:5173`. Для внешнего магазина нужен HTTPS-домен.
5. Настройте чеки в соответствии с параметрами магазина: `YOOKASSA_VAT_CODE` включает сбор email и передачу receipt; при необходимости заполните `YOOKASSA_TAX_SYSTEM_CODE`. Эти значения не выбираются автоматически.
6. В кабинете ЮKassa добавьте webhook `https://ВАШ-ДОМЕН/api/webhooks/yookassa` для `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Локальный адрес извне недоступен. После возврата клиента статус также проверяется через API провайдера.
7. Пройдите тестовую оплату, возврат, активацию ключа и экспорт. Затем замените реквизиты на боевые и поставьте `YOOKASSA_TEST=false`. Реальные платежи в рамках разработки не выполнялись.

Официальная документация: [создание платежа](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start), [проверка уведомлений](https://yookassa.ru/developers/using-api/webhooks).

Сервер сам задаёт цену, сверяет сумму, валюту, магазин, ID заказа, тестовый режим и статус платежа. Повторная обработка не выдаёт дополнительный ключ. Ключ хранится в базе в виде SHA-256; исходный ключ восстанавливается только владельцу заказа по секрету сервера. Возврат денег отзывает ключ. Заказы привязаны к HttpOnly-cookie браузера; после покупки пользователь должен сохранить ключ. Отправка ключа на email не реализована — email используется только для чека при включённой фискализации.

Экспорт резервирует разовое скачивание, подтверждает его после подготовки файла и освобождает при ошибке. Зависший резерв освобождается через 10 минут. Браузер не сообщает, сохранил ли пользователь файл в системном диалоге: считается успешная подготовка и запуск скачивания.

### Развёртывание и границы защиты

`npm run build`, затем `npm start` обслуживает `dist` и API одним Node-сервером на `127.0.0.1:3001`. Поставьте перед ним HTTPS reverse proxy, задайте `NODE_ENV=production` и правильный `APP_ORIGIN`. SQLite-файлы `data/` должны находиться на постоянном диске с резервными копиями. Текущая реализация рассчитана на один серверный процесс. Статический хостинг без Node API для оплаты не подходит; существующий `.openai/hosting.json` не разворачивает платёжный сервер.

Перед публичным приёмом денег добавьте реальные реквизиты продавца, контакты, оферту и политику обработки данных; сейчас таких данных владелец не предоставлял. Не публикуйте сайт как готовый к реальной оплате без настройки магазина и проверки чеков.

**Ограничение:** генерация изображения и HTML остаётся в браузере, а API контролирует штатный процесс скачивания. Это не DRM: пользователь с инструментами разработчика может обойти клиентский интерфейс или сделать скриншот. Для строгой защиты платных файлов потребуется серверная генерация и выдача файлов; в текущем варианте тексты и фотографии не передаются серверу.

## Статьи и SEO

`content/articles.json` содержит шесть оригинальных инструкций: создание диалога, формат JSON, оформление iPhone, экспорт, сценарии для мемов и фотографии. `content/semantics.json` — карта запросов по задачам пользователей, целевые страницы и исключённые темы. Это качественная семантика по выдаче и анализу конкурента; частотности Wordstat и фактические позиции не измерялись.

Главная — `/`, база знаний — `/blog/`, статьи — `/blog/<slug>/`. При `npm run build` скрипт `scripts/prerender.mjs` записывает готовый HTML каждой страницы: текст доступен без JavaScript. Добавляются уникальные title/description, canonical, Open Graph, Article/BreadcrumbList, FAQPage на главной, sitemap.xml и robots.txt. Обещаний расширенного поискового сниппета или позиций в топе нет.

Перед публичной сборкой задайте одинаковый HTTPS-домен в `SITE_URL` и `VITE_SITE_URL`. Пока используется localhost, сборка запрещает индексацию в robots.txt и meta robots. После изменения домена пересоберите проект. В `npm run dev` метаданные устанавливаются браузером; проверять готовый HTML нужно в `dist` или через production-сервер.

Раздел отзывов содержит заметно подписанные демонстрационные тексты без вымышленных имён клиентов, рейтинга и статистики. Заменяйте их только реальными отзывами с разрешения авторов. Разметка Review/AggregateRating намеренно отсутствует.

При размещении на стороннем статическом хостинге настройте раздачу вложенных `index.html` для статей и отдельного `/app/index.html` для редактора. Не перенаправляйте все URL на главную: это создаёт одинаковые страницы вместо статей. В Node-сервере проекта нужные статические страницы и ответ 404 уже предусмотрены. Затем добавьте домен в Яндекс Вебмастер/Google Search Console и отправьте sitemap.
